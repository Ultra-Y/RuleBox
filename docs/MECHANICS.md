# RuleBox 机制说明

> 对应代码：`src/rulebox/core/` 与 `src/rulebox/ui/`。测试基线 130 条。
> 这份文档解释“玩家看到的规则”和“代码实际的结算顺序”。

## 1. 世界模型

- 网格是二维数组，每格是一个**实体列表**，从底到顶排列；通常一格一个实体，只有「你」可以和非实心物件重叠。
- 坐标 `(row, col)`，左上角为 `(0, 0)`。
- 每个实体有 `id`、`kind`（`object` / `word`）、显示文字、颜色。
- 物件包括：人、墙、箱、旗、水、火、石、门、钥、传送门；词块包括名词、`是/和/不`、属性词。
- 地图外是边界，不能离开。

## 2. 一回合的结算顺序

玩家按一次方向键，执行顺序固定为：

1. **快照**：把当前所有格子压入历史，供撤销；
2. **解析规则**：扫描横/竖连续词块，得到当前规则、属性表、变形表；
3. **找「你」**：所有带 `YOU` 属性的物件；
4. **移动 / 推链**：按从左上到右下的顺序，逐个尝试移动每个「你」；
5. **传送**：只处理这一步真正移动过的物件；
6. **接触结算**：开/关 → 水 → 热/融；
7. **变形**：按回合开始时的变形表统一替换；
8. **重新解析规则**，判断是否还有「你」；
9. **返回结果**：移动成功、胜利、失败；失败移动会整体回滚。

两个重要例外：

- **胜利会短路**：某一步接触 `WIN` 后，立刻停止后续「你」的移动，也跳过传送和接触结算；变形仍会执行。
- **移动失败会回滚**：没有任何「你」移动、也没有胜利时，整个快照弹回，历史不增加。

## 3. 规则系统

### 3.1 词块

- 词块是场上的实体，**永远可以被推**，不需要 `推` 属性。
- 词块**不参与**属性系统：不能被赋予 `停`、`赢` 等属性。
- 词块**不会被水或热摧毁**，也**不会被传送**——避免把关键词弄丢造成死局。

### 3.2 句子怎么读

- 横向从左到右、纵向从上到下，连续词块组成候选串。
- 一条句子至少 3 个词块。
- 相邻的两句（例如「墙 是 停 人 是 你」）会由 `parse_run` 切成多条句子，取句子数最多的切法。
- 同一段词块可能同时参与横向和纵向句子；完全相同的规则会去重。

### 3.3 语法

```text
名词 (和 名词)* 是 属性 (和 属性)*
名词 (和 名词)* 是 不 属性 (和 属性)*
名词 (和 名词)* 是 名词              # 变形
```

例子：

- `墙 是 停`
- `墙 和 箱 是 停`
- `人 是 你 和 推`
- `墙 是 不 停`
- `石 是 箱`

`不` 只否定属性，不否定名词，也不构成变形。

### 3.4 属性合并

- 同一名词的多条规则取并集。
- `不` 会把对应属性从并集里减掉。
- 变形表是 `名词 -> 目标名词`；同一名词有多条变形时，后解析到的覆盖前面的；但自指规则会锁住变形。
- 属性冲突时由移动逻辑决定优先级，例如 `停` 优先于 `推`。

### 3.5 自指规则锁

- `A 是 A`（如 `旗 是 旗`）会锁定 A 的变形。
- 存在锁时，`A 是 B`（B ≠ A）整句不生效：不进入变形表、不参与移动结算。
- 被拒绝的句子整句压暗，并在主语 A 的词块上画红叉。
- 自指规则优先于其他变形，与句子出现的位置/先后无关；属性规则（如 `旗 是 赢`）不受影响。
- 规则面板只列出生效规则；自指锁本身会保留在面板里，作为锁定提示。

## 4. 属性表

| 词 | 内部名 | 实际效果 | 备注 |
| :--- | :--- | :--- | :--- |
| 你 | `YOU` | 玩家控制 | 可以多个；逐个移动 |
| 推 | `PUSH` | 可被推动 | 优先于 `停`；推链失败整体不动 |
| 停 | `STOP` | 阻挡进入和推动 | 与 `推` 同时存在时可以被推 |
| 赢 | `WIN` | 「你」接触即胜 | 「你」自身带 `赢` 时，操作即胜 |
| 浮 | `FLOAT` | 不被水摧毁 | 可与水同格 |
| 热 | `HOT` | 同格摧毁 `MELT` | 自身不被自己的热毁掉 |
| 融 | `MELT` | 被 `HOT` 摧毁 | 自身同时带 `HOT` 时跳过 |
| 开 | `OPEN` | 可进入 `SHUT` 格并抵消门 | 也能抵消被推着的门 |
| 关 | `SHUT` | 阻挡，除非移动方带 `OPEN` | 与 `PUSH` 同时存在时可被推；`OPEN` 优先抵消 |
| 传 | `TELE` | 成对传送 | 恰好两个传送格才生效 |
| 败 | `DEFEAT` | 与「你」同格即判负 | 不再只是词表占位 |

> 变形不是属性，是句子形式 `A 是 B`。

## 5. 物件与默认行为

| 物件 | 默认行为 | 说明 |
| :--- | :--- | :--- |
| 人 | 无 | 需要「人 是 你」 |
| 墙 | 无 | 需要「墙 是 停」；关卡都显式放了 |
| 箱 | 无 | 需要「箱 是 推」 |
| 旗 | 无 | 需要「旗 是 赢」 |
| 水 | **内建危险** | 同格非 `FLOAT` 物件被毁；词块和水自身免疫 |
| 火 | 无 | 需要「火 是 热」 |
| 石 | 无 | 中性物件，常用来变形 |
| 门 | 无 | 需要「门 是 关」 |
| 钥 | 无 | 需要「钥 是 开」 |
| 传送门 | 无 | 需要「传送 是 传」 |
| 词块 | 永远可推 | 不参与属性、不受水/热、不传送 |

**只有水是内建行为**；墙、旗、门、钥、传送门都必须靠规则生效。这是“规则世界”的核心。

## 6. 移动、推链与占用

### 6.1 谁能动

- `you_positions` 找出所有含 `YOU` 物件的格子。
- 每回合按行优先顺序逐个移动；一个格子只移动最上层实体。
- 多个「你」不是严格同时移动；先移动的可能改变后移动者的目标格。

### 6.2 进入目标格的判定顺序

对每个移动方，按顺序检查目标格：

1. 有 `STOP` 且不可推 → 挡住；
2. 有 `SHUT` 且不可推，且移动方没有 `OPEN` → 挡住；
3. 有 `WIN`：
   - 最外层「你」→ 胜利；
   - 被推的物件 → 挡住（不能把箱子推进赢格）；
4. 有词块或 `PUSH` 物件 → 递归推链；
5. 有另一个 `YOU` → 挡住；
6. 其他占用物 → 被推物件挡住；最外层「你」可以进入并与普通物件重叠；
7. 水 / 热 / 传送门不算占用，进入后交给接触结算。

### 6.3 推链

- 推链递归：把目标物件朝同方向再推一格，成功后才移动自己。
- 任意一层失败，整条链不动。
- 词块和 `PUSH` 物件走同一套推链。
- 代码里有 `MAX_PUSH_DEPTH = 10`，但当前未真正用于截断；链长受地图宽度限制。

### 6.4 重叠

- 「你」可以进入只含普通物件（非 `STOP`/`PUSH`/`WIN`）的格子，形成叠加；离开后物件还在。
- 非「你」的物件被推时不能进入已被占用的格子，除非占用物是水、热、传送门，或门对带 `OPEN` 的推手让路。
- 两个「你」不能互相重叠。

## 7. 接触结算

移动结束后，按以下顺序对**全图**结算（不只是移动过的格子）：

### 7.1 开 / 关

- 格子里同时有 `OPEN` 和 `SHUT`：双方一起抵消。
- 自身同时带 `OPEN` 和 `SHUT` 且没有对手时不自我抵消；`OPEN` 移动方遇到 `SHUT + PUSH` 时优先抵消门，不会把门推走。
- 因此钥匙被推进门格、门被推进钥匙格、传送把 `OPEN` 送进门格，都会让双方消失。
- 如果 `OPEN` 的「你」撞门，它也会一起消失；失去最后一个「你」就判负。

### 7.2 水

- 含水格子里，所有非 `FLOAT`、非词块、非水的物件被摧毁。
- 水是内建行为，不需要「水 是 沉」。
- 带 `FLOAT` 的物件可以和水同格，离开后水还在。

### 7.3 热 / 融

- 有 `HOT` 的格子里，摧毁 `MELT` 物件。
- 同一物件同时带 `HOT` 和 `MELT` 时跳过，不自毁。
- 水先于热结算：同一格的水会先把不带 `浮` 的热/融物件冲掉。

### 7.4 传送

- 场上**恰好两个**不同的 `TELE` 格时生效。
- 只传送“本回合移动轨迹”里的物件；词块和 `TELE` 物件自身不传。
- 原地不动的住户不传；目的地不连锁；一次结算。
- 传送发生在接触结算之前，所以传进水里会被淹死，传进门格会开门。

### 7.5 变形

- 按回合开始时解析出的 `A 是 B` 表，统一替换物件。
- 词块不参与；同一物件只替换一次；新生成的目标不会在同一回合继续变形。
- 变形可能制造新的「你」，也可能消灭最后一个「你」，所以判负在变形之后重新解析规则再算。

## 8. 胜负

### 胜

- 只有「你」**尝试走进** `WIN` 格时触发。
- 把箱子推进赢格不算；站在赢格旁边不算。
- **「你」自身带 `WIN`**：操作它移动时直接胜利，即使目标格被挡住。
- 胜利短路：跳过传送和接触结算，门即使和 `WIN` 同格也不会被摧毁。
- 键盘 `Enter` / `N` 进入下一关；最后一关回选关。

### 负

- 接触结算和变形之后，如果「你」与带 `败` 的物件同格，判负。
- 或者场上没有任何「你」，也判负。
- UI 显示失败遮罩；`R` 重开、`Z` 撤销、`Esc` 菜单。
- 如果开局就没有「你」，这次移动直接无效（不是判负）。

## 9. 界面、关卡与进度

- 菜单：开始游戏 / 官方关卡 / 自制关卡 / 关卡编辑器 / 退出。
- 官方关卡分类：`教程`（01–10）/ `第一章`（1-1、1-2）；进入分类后再选具体关卡。
- 官方关卡：`content/levels/*.txt`；自制关卡：`custom_levels/*.txt`（gitignore）。
- 进度键：官方用文件 stem，自制用 `custom:<stem>`，互不干扰。
- 选关只显示标题，不显示编号和符号；已完成关卡用淡色区分。
- 生效规则中的词块保持原色；未进入任何有效句子的词块压暗（`active_word_positions`）。
- 通关记录写入 `progress.json`（gitignore）。
- 编辑器试玩不写进度，`Esc` 回到编辑器。

## 10. 关卡编辑器

- 画布 5×5 到 20×20，可增减宽高；默认 11×8。
- 调色板包含 11 个物件和 24 个词块；左键放置、右键擦除。
- 保存：写 `custom_levels/<关卡名>.txt`；保存前用 `parse_level` 校验。
- 打开：从已保存的自制关卡载入，转换回字符网格。
- 重命名 / 删除：作用于当前打开或保存过的自制关卡。
- 撤销/重做：`Ctrl+Z` / `Ctrl+Y`，最多 60 步；放置、擦除、尺寸调整、清空都可撤销。
- 试玩：直接构造 `Game`，不落盘、不写进度；`Esc` 回编辑器。
- 导出/导入分享码：分享码是关卡 DSL 的 base64；导入先解码再 `parse_level` 校验。
- 官方收录：编辑器不提供按钮，由维护者复制到 `content/levels/` 并补编号、解法和回放测试。

## 11. 已知边界与实现限制

1. 多个「你」是**顺序移动**，不是严格同时；顺序为行优先。
2. `MAX_PUSH_DEPTH` 目前没有真正截断推链。
3. 传送落点**不重新检查** `STOP`/`SHUT`；可以传进被挡住的格。
4. `OPEN` 移动方遇到 `SHUT + PUSH` 时优先抵消门，不推门。
5. 胜利短路会让同格的 `SHUT` 门保留下来；游戏已结束，不影响胜负。
6. `败` 只在「你」与其同格时判负，不会主动追踪。
7. 接触和变形都用**回合开始时**的属性；这一回合推词改出的新规则，下一回合才生效。
8. 水会摧毁不带 `浮` 的传送门；关卡设计时通常给传送门加 `浮`。
9. 墙、旗、门、钥、传送门没有内建行为；关卡必须显式写规则。
10. 关卡目前是教程 01–10 + 主线 1-1/1-2；主线 1-3 及后续待补。没有提示系统、`validate.py`、最佳步数。
11. 编辑器没有撤销/重做，最大 20×20；自制关卡不会自动进官方目录。
