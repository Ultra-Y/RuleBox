## 边界决定

1. **判定顺序**：STOP → SHUT → WIN → PUSH → 占用。SHUT 在 WIN 之前（按你的建议）：没有 OPEN 的「你」被门关住时连赢物件都碰不到。
2. **OPEN 走进 SHUT+WIN 格**：判胜，但门此时**不被摧毁**——现有 WIN 是短路语义（won 时既不移动实体也不跑接触结算），我沿用它而不是改 WIN 路径。`test_open_you_wins_through_shut` 把这个选择锁死。
3. **SHUT + STOP 同格**：STOP 先判，OPEN 也过不去。
4. **词块**：既没有 OPEN 也打不开门（推词进 SHUT 整步失败、不留快照），也不传送。
5. **门的摧毁按"同格"结算**（与水/热一致）：格子里同时存在 OPEN 与 SHUT 就毁门，因此变形或传送造出的同格也会开门；自身同带 OPEN 的 SHUT 跳过。
6. **传送只认"这一步进入传送格的物件"**（用移动轨迹 + 移动后的实际位置判定）。我先试了"整格扫描"的写法，发现会让目的地的住户每回合被弹回来（A↔B ping-pong），所以改成轨迹版：住户不动、不连锁、TELE 自身不传。
7. **恰好两个 TELE 格**才生效；两个 TELE 挤在同一格只算一个格 → 不传送。
8. **规格与既有实现的唯一冲突**：B1/B4 要求"被推的箱子也能传进水里淹死"，但 5.1 的占用规则会拦住任何被推物件进入有物件的格子。最小改动是让 TELE 物件不占地（`is_obstacle` 里让路，和水/热同级），否则传送只对「你」自己走空格有效。
9. **水 + 传送门同格**：水会把无 `FLOAT` 的传送门一起淹掉（既有 5.3 行为），所以 `test_teleport_into_water_drowns_you` 给门加了「传 和 浮」来隔离这条断言。
