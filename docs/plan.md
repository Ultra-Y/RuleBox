## 1. 游戏概念

### 1.1 电梯演讲

> 这是一款中文词块解谜游戏。场地里的墙、箱子、旗子，以及"什么能推、什么会挡、什么算赢"，全都由可推动的词块决定。把「墙 是 停」这句话推散，墙就变回普通地板；拼出「箱 是 赢」，箱子就成了终点。你要做的不是把箱子推到指定位置，而是**改写这个世界的规矩**。

### 1.2 核心循环

| 阶段 | 玩家在做什么 | 典型时长 |
| :--- | :--- | :--- |
| 观察 | 读场上的规则句，认出这关的新东西 | 5–10 秒 |
| 推理 | 问自己"哪条规则挡着我，哪条能帮我" | 10–60 秒 |
| 操作 | 推词块、推箱子，走一步算一步 | 5–30 秒 |
| 反馈 | 规则成立/失效的瞬间：发光、音效、物件行为变了 | < 1 秒 |
| 推进 | 过关、看步数、下一关 | 2 秒 |

**循环的钩子**：每一关都给你一条"看起来天经地义"的规则，然后让你亲手把它拆掉。

### 1.3 设计支柱

1. **规则是实物**：规则不是菜单里的开关，而是场地上看得见、推得动、拆得散的词块。
2. **一关一个洞察**：每关只教一件事，通关靠"想通"，不靠手速。没有追逐、没有计时、没有随机。
3. **失败零成本**：无限撤销、一键重开，鼓励玩家大胆试错——因为试错本身就是玩法。

### 1.4 参考与差异

| | 推箱子（Sokoban） | Baba Is You | **RuleBox** |
| :--- | :--- | :--- | :--- |
| 规则 | 固定 | 可改写 | 可改写 |
| 词块 | 无 | 英文 | **中文** |
| 关卡量 | 多 | 200+ | **12 关精选** |
| 目标 | 箱子归位 | 多样 | 每关一个洞察 |
| 附加 | 无 | 大量属性 | 12 属性 + 校验工具 + 编辑器（P2） |
| 定位 | 经典 | 神作 | **小而完整的"规则玩具"** |

**差异化**：

- 中文词块（「墙 是 停」比 "WALL IS STOP" 更亲切，也更适合中文玩家）；
- 12 关精选而非海量关卡，每关都可控、可测、可讲清设计意图；
- 结算顺序、属性交互写成文档并用测试锁死——不是"能跑就行"；
- 关卡校验器：每关必须有可回放的解，防止出现"设计者以为有解"的假关。

> 机制灵感来自《Baba Is You》，但**代码、关卡、美术全部原创**，不复制其资源与关卡；README 中明确致谢。

### 1.5 目标情绪曲线

```text
好奇 ──► 困惑 ──► 试探 ──► 顿悟 ──► 掌控 ──► 期待下一关
（这关新东西）（哪条规则碍事）（推一下试试）（原来可以这样）（我真聪明）（这次又是什么）
```

一关的理想时长：1–5 分钟；卡住不超过 10 分钟（有提示兜底）。

### 1.6 不做什么

- 不做战斗、血量、敌人 AI；
- 不做计时、排行、联网；
- 不做程序生成关卡（规则类谜题生成极难保证"有趣且有解"，改为手工设计 + 编辑器）；
- 不追求 3D、粒子特效大片、剧情演出；
- 不做英文版（先中文，代码内保留 i18n 结构）。

## 2. 玩法设计

### 2.1 世界元素

| 显示 | 内部 id | 初始规则示例 | 作用 |
| :--- | :--- | :--- | :--- |
| 人 | `baba` | 「人 是 你」 | 玩家操控的对象 |
| 墙 | `wall` | 「墙 是 停」 | 挡路 |
| 箱 | `box` | 「箱 是 推」 | 可推动的箱子 |
| 旗 | `flag` | 「旗 是 赢」 | 目标 |
| 水 | `water` | 无 | 进入即毁，除非「浮」 |
| 火 | `fire` | 「火 是 热」 | 摧毁「融」 |
| 石 | `rock` | 无 | 中性物件，常被用来变形 |
| 门 | `door` | 「门 是 关」 | 挡路，可被「开」打开 |
| 钥 | `key` | 「钥 是 开」 | 开门 |
| 传送 | `portal` | 「门 是 传」 | 成对传送 |
| 词块 | `word:*` | — | 规则的载体，始终可推、不可毁 |

**设计约定**：

- 词块**永远可以被推**，且**不会被水/火摧毁**——避免"把关键词推没了"造成不可恢复的死局；
- 词块不参与属性规则（不能给「词块」加「停」），降低规则系统的复杂度；
- 所有物件的行为都来自规则；唯一的内置物理是"水会淹死非浮物体"和"墙外是边界"。

### 2.2 词块与规则语法

场地上连续排列的词块自动组成句子，**横向从左到右、纵向从上到下**读取。

```text
句子 := 名词 (和 名词)* 是 属性 (和 属性)*
      | 名词 (和 名词)* 是 名词          # 变形
属性 := (不)? 属性词
```

**例子**：

| 场上词块 | 含义 |
| :--- | :--- |
| 墙 · 是 · 停 | 墙挡路 |
| 箱 · 和 · 旗 · 是 · 停 | 箱子和旗子都挡路 |
| 墙 · 是 · 不 · 停 | 墙不挡路（把规则反着写） |
| 石 · 是 · 箱 | 所有石头变成箱子 |
| 人 · 是 · 你 | 人由玩家控制 |

**词表**（首批）：

- 名词：人、墙、箱、旗、水、火、石、门、钥、传送
- 连接：是、和、不
- 属性：你、推、停、赢、浮、热、融、开、关、传、败

**语法约束**：

- 一条句子至少 3 个词块；
- 同一名词可以同时拥有多条规则，属性取并集；
- 「停」优先于「推」：既停又推的物体推不动；
- 「不」只否定紧随其后的属性，不嵌套。

### 2.3 属性语义

| 属性 | 效果 | 边界说明 |
| :--- | :--- | :--- |
| 你 | 玩家控制，可多个对象同时为「你」 | 没有「你」时判负（提示重开） |
| 推 | 可被推动 | 推链最多 10 层，防止死循环 |
| 停 | 阻挡移动与推动 | 优先于「推」 |
| 赢 | 接触即获胜 | 与「败」同时触发时，赢优先 |
| 浮 | 不被水摧毁 | 可停在水面上 |
| 热 | 接触时摧毁带「融」的物体 | 热物体本身不受影响 |
| 融 | 被「热」摧毁 | — |
| 开 | 进入「关」的格子时打开它 | 门被打开后变成空地 |
| 关 | 阻挡；可被「开」打开 | — |
| 传 | 进入后传送到另一个「传」 | 恰好一对时生效 |
| 败 | 接触即失败 | 终止本局，提示重开 |

### 2.4 交互矩阵（摘要）

| 移动方 \ 目标格 | 空 | 停 | 推 | 赢 | 败 | 水 | 热+融 | 关 | 传 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 普通「你」 | 进入 | 挡住 | 推 | 胜 | 负 | 毁（除非浮） | 融被毁 | 挡住 | 传送 |
| 带「浮」 | 进入 | 挡住 | 推 | 胜 | 负 | 进入 | — | 挡住 | 传送 |
| 带「开」 | 进入 | 挡住 | 推 | 胜 | 负 | 毁 | — | 开门进入 | 传送 |
| 带「热」 | 进入 | 挡住 | 推 | 胜 | 负 | 毁 | 毁掉对方 | 挡住 | 传送 |

（完整矩阵见附录 C，测试逐格覆盖。）

### 2.5 回合结算顺序（已冻结的设计约定）

每一步按固定顺序执行，避免"顺序不同结果不同"的玄学：

1. 读取方向输入；
2. 按当前局面解析规则；
3. 收集所有「你」对象；
4. 同时计算移动与推链（推不动则整体不动）；
5. 结算接触效果：赢 / 败 / 水 / 热融 / 开关 / 传送；
6. 结算变形规则（A 是 B）；
7. 重新解析规则（词块可能被推动了）；
8. 判定胜负（无「你」判负，接触到「赢」判胜）；
9. 保存快照（供撤销）。

> 这个顺序会原样写进 README，并用一张"顺序敏感"的测试局面锁死。

### 2.6 关卡进程

**第一章 · 认识规则（教会操作与"规则存在"）**

| # | 关卡 | 新东西 | 一句话洞察 |
| :-: | :--- | :--- | :--- |
| 1 | 第一步 | 移动、旗是赢 | 走到旗子就赢了 |
| 2 | 让开 | 推箱子 | 挡路的箱子可以推开 |
| 3 | 拆墙 | 词块可推 | 「墙 是 停」的「停」被推走，墙就不挡了 |

**第二章 · 改写世界（学会主动利用规则）**

| # | 关卡 | 新东西 | 一句话洞察 |
| :-: | :--- | :--- | :--- |
| 4 | 箱子是赢 | 改写「赢」 | 把「旗 是 赢」改成「箱 是 赢」，箱子就是终点 |
| 5 | 换个人 | 改写「你」 | 「石 是 你」——控制石头而不是人 |
| 6 | 石头变箱 | 变形规则 | 「石 是 箱」把石头变成可推的箱子 |

**第三章 · 逻辑（组合规则）**

| # | 关卡 | 新东西 | 一句话洞察 |
| :-: | :--- | :--- | :--- |
| 7 | 和 | 「和」 | 「墙 和 箱 是 停」——拆掉「和」只解一半 |
| 8 | 不 | 「不」 | 「墙 是 不 停」——负负得正 |
| 9 | 两条规则 | 同时维持两条句子 | 一边推词块一边推箱子，两条规则都不能散 |

**第四章 · 机关（空间机制组合）**

| # | 关卡 | 新东西 | 一句话洞察 |
| :-: | :--- | :--- | :--- |
| 10 | 浮 | 水 + 浮 | 给箱子「浮」，它就能漂过水 |
| 11 | 融 | 火 + 融 | 「火 是 热」「箱 是 融」——用火清出一条路 |
| 12 | 门与传送 | 开/关 + 传 | 先开门，再借传送绕过墙 |

> 每章 3 关，正好是一个"引入—练习—组合"的小节奏；第 12 关是结业关。

### 2.7 无文字教学

- 不弹教程框、不写长提示；
- 第 1 关只放两条规则，玩家自己发现"走到旗子就赢"；
- 新机制第一次出现时，只在**必然经过的路径**上放最小示例；
- 关卡名就是提示（「拆墙」比"第三关"有用）；
- 规则面板实时显示当前生效的句子，把"隐性规则"显性化。

### 2.8 手感与反馈（juice 清单）

| 事件 | 反馈 |
| :--- | :--- |
| 移动 / 推动 | 90 ms 缓动，推链逐格错开 30 ms |
| 规则成立 / 失效 | 相关物件描边发光 0.2 秒，规则面板同步刷新 |
| 水淹 / 融化 | 粒子 + 轻微震屏 |
| 开门 / 传送 | 门淡出、传送环收缩 |
| 过关 | 彩纸粒子 + 步数统计 + "新纪录"标记 |

**配色**：名词词块蓝、连接词灰白、属性词橙；物件用高对比几何色。整套视觉只用代码绘制（圆、方、三角、波浪），不依赖图片素材。

### 2.10 难度设计

- **难度只来自"想通"，不来自"操作"**：不做限时、不做长推链、不做手速；
- 每关只有一个核心洞察，但允许 2–3 种解法；
- 误导要有，但不能是"看起来能走其实必死"的恶意设计；
- 卡关 10 分钟给提示，提示只指方向（"试试拆掉「停」"），不给步骤；
- 试玩中若 3 人都卡在同一处，优先改关卡而不是加提示。

### 3.6 移动与推链

```python
def try_move(world, coord, direction) -> bool:
    target = coord + direction
    if out_of_bounds(target) or has_prop(world, target, "STOP"):
        return False
    if has_prop(world, target, "PUSH"):
        if not try_move(world, target, direction):   # 递归推链
            return False
    move_object(world, coord, target)
    return True
```

- 推链深度上限 10，超过视为推不动；
- 多个「你」同时移动：先按坐标排序计算意图，再统一提交；两个对象抢同一格时，先到者得，后者原地；
- 词块与箱子走同一套推链逻辑，特殊之处只在"词块不可毁"。

### 3.7 接触结算

按 2.5 的顺序执行，关键点：

- **水**：非「浮」物体进入水格即消失；水本身不移除；
- **热/融**：带「热」的物体进入带「融」的物体格，后者消失，前者占位；
- **开关**：带「开」的物体进入带「关」的物体格，门消失，前者占位；
- **传送**：进入「传」格后立即移动到配对的另一个「传」格；恰好一对才生效；
- **变形**：`A 是 B` 在移动结算后统一替换，避免"边走边变"的歧义；
- **胜负**：接触「赢」立即胜；接触「败」立即负；同时发生时胜优先。

### 3.8 撤销与重放

- **快照**：每步深拷贝 `cells`（≤ 300 格，开销可忽略），撤销就是弹出快照；
- **重放**：`solutions/XX.txt` 存 `URDL` 字符串，校验器从初始局面重放，断言最终胜利；
- **好处**：关卡"有解"可被程序证明，改引擎后所有关卡自动回归。

### 3.9 关卡格式

自定义文本 DSL，纯文本、可 diff、手写不痛苦：

```text
name 03 拆墙
size 11 7

legend
  # wall
  . empty
  @ baba
  $ box
  F flag
  W word 墙
  I word 是
  S word 停

grid
  ###########
  #.........#
  #..@..WIS.#
  #.....$...#
  #.........#
  #........F#
  ###########
```

- `legend` 一行一个符号：`符号 类型 [id]`；
- `word` 类型的 id 是词本身（墙/是/停/你/推/赢…）；
- 关卡文件名即编号，`solutions/` 下同名文件存解法。

### 3.10 工具

- **`validate.py`**（P0）：解析全部关卡 → 检查尺寸、初始至少一个「你」和一个「赢」 → 回放解法 → 断言胜利。任何一项失败，CI/提交前直接红。
- **`editor.py`**（P2）：游戏内网格编辑器，点选调色板放物件/词块，保存 DSL，一键试玩。它同时是内容生产效率工具和"给玩家的玩具"。

### 3.11 性能与确定性

- 网格最大 20×15，每回合 O(格数) 解析规则，纯 Python 绰绰有余；
- 游戏是回合制，无随机数，**同一串输入必然得到同一局面**——这让回放、测试、撤销都变得简单；
- 渲染 60 FPS，动画只影响表现层，不参与逻辑结算。

## 4. 内容生产（关卡设计）

### 4.1 一关是怎么设计出来的

每关都按同一个模板写，先纸面后实现：

1. **一句话洞察**：这关要玩家发现什么？（写不出来就别做）
2. **初始规则**：场上有哪几条句子，哪条是真规则，哪条是诱饵；
3. **关键三步**：从开局到通关，最少需要哪几个"有意义的操作"；
4. **误导与反制**：哪条路看起来可行但走不通，为什么；
5. **验收**：写出 `URDL` 解法 → 校验器回放通过 → 请 1 人试玩。

### 4.2 关卡清单

见 2.6 的 12 关表。补充原则：

- 第 1–3 关总时长不超过 3 分钟，先让人尝到"推规则"的甜头；
- 第 4 关是第一个"哇"时刻，必须足够干净（只有一条误导）；
- 第 9、12 关是组合关，允许 2–3 种解法，不追求唯一解；
- 关卡数与难度都不再增加，除非前 12 关试玩反馈"太短"。

### 4.3 关卡验收（每关必须全过）

| 检查 | 方法 | 失败处理 |
| :--- | :--- | :--- |
| 能解析 | `validate.py` 解析不报错 | 修格式 |
| 有「你」 | 初始规则解析后存在 YOU | 补规则 |
| 有「赢」 | 初始规则解析后存在 WIN | 补规则 |
| 有解 | 回放 `solutions/XX.txt` 通关 | 重设计或补解法 |
| 不恶心 | 试玩不出现"必死但看不出来"的走法 | 加提示或改布局 |
| 不冗长 | 最优解 ≤ 25 步 | 缩小地图 |

### 4.4 试玩与迭代

- 每周至少找 1 位同学试玩当周新增关卡；
- 记录：卡住时长、第一次错在哪、是否用到提示；
- 规则：同一处卡 3 人 → 改关卡；卡 1 人 → 加环境暗示；
- 试玩记录放进 `docs/playtest.md`，作为"验证"的一部分。

### 4.5 难度曲线

```text
难度
 ▲
 │                    ● 12
 │              ● 9
 │        ● 6
 │   ● 3
 │ ● 1
 └──────────────────────────► 关卡
   认识规则   改写世界   逻辑   机关
```

每章内部也是"易—中—难"，避免连续两关都卡。

## 附录 A · 规则语法与解析

```text
句子 := 名词 (和 名词)* 是 属性 (和 属性)*
      | 名词 (和 名词)* 是 名词
属性 := (不)? 属性词
```

解析伪代码：

```python
def parse(words):
    nouns, props, transform, negated = set(), set(), None, set()
    i = 0
    # 名词段
    while i < len(words) and words[i].text in NOUNS:
        nouns.add(words[i].text)
        i += 1
        if i < len(words) and words[i].text == "和":
            i += 1
            continue
        break
    if not nouns or i >= len(words) or words[i].text != "是":
        return None
    i += 1
    # 「不」
    if i < len(words) and words[i].text == "不":
        negated_flag = True
        i += 1
    # 属性段 / 变形段
    while i < len(words):
        if words[i].text in NOUNS and len(nouns) == 1:
            transform = words[i].text
            i += 1
        elif words[i].text in PROPS:
            props.add(words[i].text)
            i += 1
        else:
            return None
        if i < len(words) and words[i].text == "和":
            i += 1
            continue
        break
    return Rule(nouns, props, transform, negated)
```
